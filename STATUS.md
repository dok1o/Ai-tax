- Sol fix for Astra's T-016 finding (the app reached the network on a corrupt tokenizer cache) is pushed to `arena/ad3092b4-ai-tax`; the T-011 row stays in review. Reproduced with tripwires on `urllib.request.urlopen`, `socket.create_connection`, `socket.getaddrinfo`, `socket.socket.connect` and `requests.get`: a corrupt cached BPE file made `tiktoken.load.read_file_cached` delete it and call `requests.get`, and an incomplete Hugging Face snapshot made `AutoTokenizer.from_pretrained(..., local_files_only=True)` open a socket to huggingface.co. Root cause: the pre-flight only checked that a file existed. `app/tokenizers.py` now verifies each cache before any loader runs — the tiktoken file must exist, be readable, be non-empty and match the sha256 that the installed registry publishes (read by ast from `tiktoken_ext/openai_public.py`, never by calling it), an empty `TIKTOKEN_CACHE_DIR` is reported as a download risk because tiktoken then disables caching, and the hub snapshot for the pinned revision must hold a readable `tokenizer.json`/`tokenizer_config.json`. Both loaders also run with their download path blocked: `tiktoken.load.read_file` is replaced by a tripwire that raises `OfflineCacheError`, and `from_pretrained` runs inside forced offline mode (`HF_HUB_OFFLINE`/`TRANSFORMERS_OFFLINE` plus `huggingface_hub.constants.HF_HUB_OFFLINE`, restored afterwards) on top of `local_files_only=True`. A failure disables that tokenizer with the reason shown in the sidebar and the Method tab; nothing is tokenized, and a corrupt cache file is no longer deleted. Regression tests in `tests/arena/test_tokenizers.py` (7 new) assert zero network attempts for a corrupt tiktoken cache, an incomplete snapshot, and a direct call of each loader. `python run.py check`: ruff clean, 181 passed, validator 60 questions / 180 rows.
